## 3. Decisions worth remembering

- **Tracing is manual, not auto-instrumented.** The gateway needs one span per upstream
  attempt with TTFT and attempt number; auto-instrumentation cannot express that and
  monkey-patches httpx, which complicates injected test clients. See
  `notes/observability.md`.
- **Metrics are opt-in with a separate port.** Route labels use the matched template, never
  the concrete path; TTFT is a histogram because a per-request trace value cannot be
  aggregated.
- **Model access defaults to allow.** Existing deployments keep working; restriction is an
  explicit per-tenant allowlist. Empty allowlist means "no models", intentionally.
- **Costs are stored, prices are versioned.** `effective_from` rows are never edited;
  historical cost is frozen on the usage row. Money is `NUMERIC(18,6)` and `Decimal`.
- **Plans are token allowances; overage is a switch.** Inside the plan is free, above it is
  list price. `plan_allow_overage=false` blocks at exhaustion; `true` bills overage and the
  cost budget is the hard cap.
- **No pre-call reservation.** Accepted overshoot is bounded by in-flight requests; recorded
  as a non-goal with the condition that would justify revisiting it.
- **Admin audit is best effort.** The action already happened; a failed audit write is
  counted and logged, never silently dropped. Only business fields are stored.
- **Master key stays as break-glass owner.** Sessions are the browser credential, CSRF is a
  double submit, and disabling the master key requires an existing owner or startup fails.
- **Prompt limits are character budgets.** No provider tokenizer exists; the error names the
  field so clients can react.
- **Deployment credentials are environment variable names.** No secrets in the database; the
  pool resolves and caches clients per `(provider, env var, base_url)`.
- **Cooldown is process-local.** Shared health belongs with the Redis work (G1.2); a cooldown
  never removes the last candidate.
- **Provider retries stay inside a deployment.** Failover happens after them; lower
  `GATEWAY_MAX_RETRIES` for faster switchover.
- **The load baseline changed the plan.** A single worker saturates near 100 RPS on one core,
  and the per-request month aggregate collapses at 50k rows (p95 9.94 s at 100 RPS) and cannot
  hold 60 RPS at 215k rows. G1.3 order is month counter, price cache, key/tenant cache, batched
  writes; multiple workers wait for G1.2. See `notes/load-baseline.md`.
- **Billing has a kill switch, not a fallback.** `GATEWAY_BILLING_ENABLED=false` skips the
  month aggregate and the price lookup entirely and leaves cost fields unset rather than
  guessing; re-enabling mid-period requires a backfill from versioned prices.
- **Audit lifecycle decisions.** Retention is a per-tenant override with 0 as a legal hold;
  cleanup is a CLI batch job (requests, then orphan sessions); deletion is a hard delete whose
  proof is counts plus a follow-up query; export streams with keyset pagination; redaction runs
  before hashing so prefix matching stays stable. See `notes/audit-retention.md`.
- **Lifecycle parameters are bounded and explicit.** The pool is configuration (not CPU-derived,
  which hides replica multiplication); `statement_timeout` is server-side so the backend actually
  stops; drain is tracked at the ASGI boundary with a pure middleware because
  `BaseHTTPMiddleware` returns before a stream ends; the idle timeout bounds the gap between
  chunks, not the total stream. Workers are wired but stay at 1 until G1.2. See `notes/runtime.md`.
- **Rate limits are a shared token bucket.** Capacity and refill both derive from
  `requests_per_minute`; one Lua script makes refill-and-take atomic across replicas; a backwards
  clock only under-refills. The default failure policy is fail-open with
  `gateway_rate_limit_degraded`, because a limiter outage should not take down inference;
  fail-closed is opt-in and also gates readiness. See `notes/rate-limiting.md`.
- **TPM is post-paid.** Token counts only exist after the provider responds, so a request is
  admitted while the bucket is above zero and the reported usage is charged at settlement. The
  overshoot is one request, matching the no-reservation billing decision; the next call sees a
  negative bucket and gets 429 `token_rate_limited`. Per-key and per-model buckets are separate
  scopes, so a key limit is enforced on top of its tenant's.
- **Provider differences live in adapters.** Azure subclasses the OpenAI adapter (deployment path,
  `api-key`, `api-version`); Anthropic is a full Messages translation including tools and SSE.
  Model capabilities (`context_window`, `max_output_tokens`, `supports_tools`,
  `supports_streaming`) are declared at registration and enforced before the upstream call.
  See `notes/providers.md`.
- **Tenant deletion is a soft delete.** `deleted_at` hides the tenant, its lookups return
  not-found, and all keys are revoked; usage and audit rows stay for foreign keys and history.
  Hard deletion is rejected because billing and audit data must not vanish with the tenant.
- **Capabilities are editable.** Model PATCH accepts the four capability fields, so the request
  guard can be corrected without recreating the model; explicit null clears a numeric limit.
- **Focus is part of the contract.** Dialogs keep focus inside after a view swap, destructive actions move focus to the panel title when the trigger disappears, and admin forms lock while pending and announce errors. See `notes/ui-audit.md`.
- **Capabilities are metadata, not a tokenizer.** `context_window` is recorded for capacity work;
  only `max_output_tokens` and the two boolean supports are enforced, because the gateway has no
  model-specific tokenizer.
- **Concurrency is a lease with a TTL.** Slots are acquired before the upstream call and released
  in a `finally` (the SSE generator's shielded one for streams). The Redis lease expires after
  `GATEWAY_CONCURRENCY_LEASE_SECONDS`, so a crashed worker leaks at most one slot; TTL refresh can
  briefly over-admit a stream that outlives it, which is safer than a permanently dead slot.
- **Cooldown is shared, and degrades open.** The failure counter and deadline live in Redis when
  configured; Redis errors are counted (`gateway_cooldown_degraded`) and treated as available,
  because routing already retries and falls back and must not stall on its health store.
- **Monthly enforcement reads a same-transaction rollup.** `tenant_month_usage` is upserted with
  each usage row, so detail and rollup cannot diverge; month-aligned windows read one row and other
  windows still aggregate detail. Price and key/tenant caches were rejected because the measured
  cost was the aggregate, and caching would delay price activation and key revocation. Batched
  writes are deferred until a measurement demands them. See `notes/hot-path.md`.
- **The rollup removed the collapse.** 215k rows at 60 RPS went from 39.6 RPS at p95 15.3 s to
  60 RPS at 48 ms, matching the same-day baseline; 100 RPS now fails on single-worker CPU, not on
  the database. The next capacity step is workers with the Redis backend.
